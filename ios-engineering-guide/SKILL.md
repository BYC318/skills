# iOS 工程知识路由

为任何 iOS 编码任务提供少量、相关、可验证的工程指导，在代码落地前主动规避高级开发者能够预见的正确性、性能、资源和生命周期问题，而不是等待故障出现后返工。用户只需描述要实现或修改的功能，不需要主动列出潜在风险；技能根据实际实现路径判断需要哪些知识。此技能是跨项目的通用知识库，不读取或依赖任何具体项目的经验库。仓库规则、当前代码和测试决定项目的具体做法；Apple/Swift 官方契约、安全、隐私和数据正确性构成不可突破的技术边界，冲突按下方规则处理。

## 按需加载

1. 任何 iOS Swift/Objective-C 编码任务都先启用本技能。不得要求用户在提示词中写出“内存、耗电、渲染、并发、网络”等关键词才启用。
2. 在最小必要范围内读取当前仓库规则、目标文件、相邻调用点和相关构建/依赖信息，先判断计划实现的行为、用户路径、系统或第三方 API，以及数据规模、线程、生命周期、失败恢复和 UI 更新边界；不以已经出现故障或已有运行证据作为加载前提。
3. 完整阅读 [知识索引](references/INDEX.md)，不要先遍历 `references/cards/`。索引中的任务信号是 AI 从代码和证据中推导的路由条件，不是要求用户提供的提示词。
4. 根据已经识别的实现决策、技术栈和可预见风险，在编码前选择能改变当前设计、实现或验证方式的知识卡。默认最多 3 张；确有多个独立风险时最多 5 张。
5. 只读取命中的卡片。纯 Model、无 UI 算法或简单常量修改可以命中 0 张，不得加载渲染、动画等无关卡片。
6. 编码前把卡片转换为本任务的少量检查项；不要向用户复述整张卡片。索引映射到 `before-coding.md` 时在编码前读取一次。
7. 实现完成后只读取命中的领域验收 checklist，并按风险执行最低充分验证。
8. 没有知识卡命中时，不为凑足数量加载相邻主题。若任务仍涉及不确定或版本敏感的 iOS 技术决策，执行下方“官方资料强制兜底”；否则记录已完成路由但无需额外知识卡，继续按仓库规则完成任务。

不得因为本技能自动读取 `~/Documents/Obsidian/GS/TaskSummary/`、其他项目目录或历史聊天。只有用户另外明确要求项目经验时，才由对应机制独立处理。

## 预防式应用

- 知识卡首先是编码前约束。只要计划使用的 API、数据流、交互路径或生命周期命中索引，就应在实现前读取对应卡片，不等待内存峰值、耗电、卡顿、错图、竞态或数据丢失实际发生。
- 从代码主动推导风险：例如远程图片列表意味着解码与缓存、Cell 复用、请求取消和身份校验；Timer 意味着计时语义、唤醒与所有者生命周期；副作用网络请求意味着错误分层、幂等性和取消；凭据落盘意味着 Keychain 与数据保护。
- 优先应用低成本、稳定且能避免返工的约束，例如明确所有权、取消、错误和缓存边界。需要改变缓存容量、并发度、刷新率、算法或模块结构的性能决策仍须测量，不得把“主动预防”变成预先堆叠抽象、缓存和并发。
- 启用技能不等于必须读取知识卡。只有卡片会实质改变当前实现或验证决策时才加载；简单 Codable 字段、常量或文案修改可以为 0 张。

## 冲突处理

iOS 工程指南提供跨项目的工程原则和默认防线，不替代项目自身的业务规则、架构约定和代码规范。发生冲突时按以下规则处理：

1. **先区分冲突类型。** 判断冲突属于业务目标、项目编码规范、技术选型差异，还是平台 API、系统版本、安全或数据正确性限制。知识卡推荐的具体技术不是强制方案；其所有权、生命周期、取消、线程安全、资源和正确性约束才是需要迁移到当前实现的原则。
2. **当前任务目标定义“做什么”。** 当前用户明确要求的业务行为和修改范围是任务目标，但不得因此突破更高层级指令、权限、安全、隐私或平台强制约束。不得为了套用知识卡而改变业务语义、扩大修改范围或擅自重构架构。
3. **当前项目决定“怎么做”。** 对所有目标文件，从 Git 根目录到目标目录逐级检查规则；每级优先读取 `AGENTS.override.md`，不存在时读取 `AGENTS.md`，同类项目规则以距离目标文件最近者为准。同时核对当前代码、测试、构建配置、最低系统版本和锁定的依赖版本。已有封装、架构或技术栈能够满足任务时优先复用。
4. **官方契约是硬边界。** 项目约定不能覆盖 Apple/Swift API 契约、availability、线程要求、安全、隐私和数据正确性。若项目现状与这些边界冲突，不得静默照做；先按“官方资料强制兜底”核实，说明冲突及证据，并提出不改变业务目标的最小安全适配。若适配会实质改变业务行为、架构、依赖或修改范围，先向用户确认。
5. **适配原则，不强推技术。** 项目使用 Combine 时，在 Combine 中落实取消、生命周期和线程隔离，而不只因知识卡提到 async/await 就迁移；项目已有 Nuke、Kingfisher 或内部图片组件时，在现有组件中落实解码、缓存、请求合并和身份校验，而不另建平行缓存；部署目标不支持新 API 时选择兼容实现。
6. **项目经验只是历史证据。** `project-memory` 不具有强制约束力，也不会由本技能自动加载。当前适用的规则、代码、测试、配置和可靠运行时证据优先；历史经验与它们冲突时视为可能过期，重新验证，不自动修改或写回项目经验。
7. **实质性取舍不得猜测。** 若冲突无法在不改变业务行为、架构、依赖、安全例外或修改范围的前提下解决，向用户说明冲突双方、影响、推荐方案和替代方案，取得选择后再实施。
8. **冲突结论不自动沉淀。** 当前任务中的临时取舍不会自动写入全局知识库或项目经验；只有用户明确要求记录时，才进入相应知识维护流程。

## 执行中动态重路由

初始知识卡集合只是当前工作集，不在任务开始后冻结。执行过程中，只要实现方案、使用的 API、数据或生命周期边界发生变化，或者调用栈、Instruments、日志、测试、编译器诊断、运行时现象或源码检查补充了新证据，必须在修改受影响代码前重新依据 [知识索引](references/INDEX.md) 评估卡片。动态重路由是编码前预防式路由的补充，不是主要触发方式。

- 加载新证据命中的卡片；不再相关的卡片停止作为当前实现约束，不能因为已经读取就继续机械套用。
- 动态调整后仍默认最多使用 3 张；确有多个独立风险时最多 5 张。达到上限时优先保留最接近当前实现决策和可靠证据、最能改变编码结果的卡片，而不是不断追加相邻主题。
- 新增约束跨越多个领域时可以阶段化处理，每个阶段重新声明当前有效卡片和最低充分验证，不把所有可能风险一次塞入上下文。
- 新实现决策没有卡片覆盖、卡片结论与证据冲突，或出现版本不确定性时，立即转入“官方资料强制兜底”。当前源码、测试和可靠运行时证据优先于不再适用的旧卡片。
- 已经读入的内容无法从模型上下文物理删除；“停止作为当前实现约束”表示后续决策与验收不再引用它，除非新证据再次命中。

例如，实现远程图片列表前，应从 `UICollectionView`、图片解码和 Cell 复用直接路由到图片与缓存、列表滚动、任务取消；若后来又加入可交互转场，再重新评估动画卡，并替换不再影响当前阶段的卡片。

## 官方资料强制兜底

出现以下任一情况时，编码或给出确定性结论前必须主动查阅官方资料：

- 已命中的知识卡没有覆盖当前关键问题，或卡片状态为 `needs-verification`。
- 对 API 契约、线程/actor 隔离、生命周期、错误语义、安全边界或性能工具用法不确定。
- 结论依赖 Xcode、Swift、SDK、最低系统、App Store 规则或第三方依赖版本。
- 编译器诊断、运行时行为或当前源码与知识卡、模型记忆不一致。
- 存在合理疑问，错误实现可能造成数据丢失、重复业务操作、隐私泄露、崩溃、明显性能或耗电回归。

兜底检索遵循这些约束：

1. 先核对当前仓库的构建设置、依赖版本、调用点和测试，再围绕具体符号或行为做最小范围检索；不得为一个局部问题全量读取官网或知识库。
2. Apple 平台事实优先使用 Apple Developer Documentation、正式 Release Notes、WWDC、Apple 示例代码和适用的 Apple DTS 答复；Swift 语言事实优先使用 Swift.org、The Swift Programming Language 和已接受的 Swift Evolution 提案。
3. 第三方依赖优先查当前锁定版本的官方文档、发布说明和源码。社区文章、问答和搜索摘要只能帮助定位，不得单独作为确定性实现依据。
4. 明确区分“官方资料确认”“由当前源码或测试推断”“仍未验证”。官方资料没有明确答案时继续用最小实验或源码验证；仍无法确认就向用户说明不确定性，不凭印象补全。
5. 发现 Beta、预览、废弃或版本受限 API 时，显式记录工具链和 availability 边界；不得把新版本行为倒推为旧部署目标的通用规则。
6. 用户明确要求不联网时遵守该限制，改用已安装 SDK 文档、头文件、模块接口、依赖源码和本地测试；证据仍不足就停止确定性断言。

官网检索结果只服务当前任务，不因此自动新增或修改知识卡。知识沉淀仍遵守本技能的确认门槛。

## 决策原则

- 先保持业务行为正确，再处理经证据支持的性能风险。
- 优先复用项目现有组件和平台 API，不因泛化“最佳实践”增加抽象、缓存、并发或依赖。
- 性能结论必须包含场景、设备、系统/构建版本、指标和测量方法。构建成功、静态审查和模拟器截图都不能证明内存、耗电或帧性能已改善。
- 把稳定 API 契约与特定系统、runtime 或第三方库版本的实现细节分开。版本绑定内容在用于编码前重新核对官方文档或当前源码。
- `needs-verification` 只能作为调查方向；不得作为必须实施的规则。
- 不以平均 FPS 代替流畅度判断；同时关注 hitch、hang、交互响应和帧截止时间。
- 优化一个资源时说明对其他资源的影响，例如用缓存换时间、合并写入换内存、提高刷新率换耗电。

## 与现有技能的边界

本技能不复制以下专项规则：

- Swift 声明、格式、本地化和主题：使用 `swift-code-standards`。
- UIKit 约束、frame、safe area 和 RTL：使用 `uikit-layout-standards`。
- UIKit 远程页面状态：使用 `remote-page-development`。
- R.swift 资源引用、SPM 缓存、模拟器验收：使用各自已有技能。

同一任务命中这些技能时可以联合使用，但每个技能只负责自己的边界。

## 收尾

不要自动把本次经验写回知识库。只有用户明确要求更新本技能时，才把经过代码、测试、真机或可靠资料支持的结论制作成候选卡，并再次验证索引、链接和触发范围。
