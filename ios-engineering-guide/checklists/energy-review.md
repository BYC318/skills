# 能耗评审清单

先确认真实高耗能路径，再决定是否优化；不要用 API 名称推断能耗结果。

## 工作量与唤醒

- [ ] 周期任务确有产品需求，能由事件或系统通知驱动的路径没有使用轮询。
- [ ] Timer 在不可见、退出或失效时停止；允许延迟的 Timer 设置了符合体验的 tolerance。
- [ ] 重试具有退避、上限、去重和取消，弱网下不会形成唤醒风暴。
- [ ] CPU、I/O、定位、传感器、相机和媒体会话仅在用户或功能需要时运行。

## 网络与后台

- [ ] 可合并请求已批处理，可压缩数据已压缩，`URLSession` 粒度允许连接复用。
- [ ] 昂贵/受限网络策略与任务优先级匹配，不会延误用户主动操作。
- [ ] 大型可延后传输使用合适的后台机制，并允许系统在适当条件调度。
- [ ] 后台刷新不是精确定时依赖；即使未执行，数据一致性和关键流程仍正确。
- [ ] 后台任务处理取消和到期，并尽快报告完成。
- [ ] 没有通过滥用后台模式、静音音频或无意义网络活动维持运行。

## 验证证据

- [ ] 改动前后在相同设备、时长、网络、电量和温度条件下复现同一流程。
- [ ] Power Profiler 证据覆盖实际高耗能区间，并与请求、Timer 或后台活动时间线对应。
- [ ] 已记录请求数、重试数、传输字节、CPU 时间和用户可感知延迟，未以单一指标代替结论。
- [ ] 非充电真机已覆盖前后台切换、锁屏、弱网/受限网络和 Low Power Mode。
- [ ] 发布后如有数据，使用 Organizer 或 MetricKit 趋势验证；本地结果与线上结果分开表述。
