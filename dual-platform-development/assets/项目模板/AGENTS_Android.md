# Android 双端协作补充

本文件只供从双端协作入口开展 Android 任务时读取，位置在双端协作根目录。它是按路径读取的项目约定文件，不是自动加载的特殊文件名，不替代或复制源码仓库已有的规则和技能。

## 读取顺序与维护边界

1. 从 [双端项目说明.md](双端项目说明.md) 找到本端实际源码仓库、Git 根目录和技能目录；未绑定时不猜选工程。
2. 先逐级读取源码仓库 Git 根目录到目标目录的既有规则，每级优先 `AGENTS.override.md`，否则 `AGENTS.md`；非 Git 工程从约定根目录开始。
3. 读取本文件中适用的补充说明；按任务选择当前会话已发现的根补充技能及源码仓库 `.agents/skills/` 中的技能。已发现的根补充技能不要求在本文件重复列索引，仅在固定使用、选择有歧义或不在发现范围时补充必要指引。源码端已有索引可利用，没有时按需检查技能名称和描述，不要求新增索引。
4. 实际加载选中的 `SKILL.md` 和必要资源，资源路径以所属技能目录为基准。用户级或插件能力先核实可用性；下面的候选名称不代表已安装，不全量加载或安装。

双端初始化和配置更新默认只读源码端 Agent 配置，不新增、修改、删除或搬动其 `AGENTS.md`、`AGENTS.override.md`、`.agents/` 或技能。需要补充的双端说明维护在本文件；技能缺失记录在双端目录，不自动给源码仓库补配置。只有用户明确要求修改该端配置时另行处理。

本端同事仍使用仓库已有入口，无需读取本文件。已有源码规则继续适用，本文件不用于绕过它们；约定冲突且影响任务时说明冲突，先解决再执行。派生工程师 Agent 时明确传入本文件及实际源码规则、技能路径，不能假设自动继承。

## 工程取舍

从双端入口实现 Android 任务时，按 [工程取舍与改动边界](.agents/skills/dual-platform-workflow/SKILL.md#工程取舍与改动边界) 判断复用、适配或新写，保留本端架构与风格。异步结果、组件复用和生命周期变化可能使先前条件失效，保留有依据的检查与错误处理，避免逐层重复防御。上述是结合工程判断的默认原则，源码适用规则和平台契约继续遵守。代码修改使用可用的 `commenting-business-intent`；关键不确定或版本敏感的技术决策核实对应官方依据，区分平台契约与推荐实践。

## 执行能力


Android 涉及工程调查、实现或验证时，优先加载已安装的官方 `android-cli` 技能；具体设备交互和旅程测试按该技能引用的参考资料执行。双端协调能力确定角色与交付范围，Android 技能补充执行方法。纯 Android 任务可以直接使用 Android 技能，不必建立双端记录。

- 先核对 `android` 是否可调用、版本及本次子命令的 `--help`；命令可能随版本变化，不照抄旧文章或技能中缓存的参数。读取当前项目的 SDK、Gradle Wrapper、运行 JDK 和实际模块；不同 App 不共用猜测出来的配置。
- SDK、设备和工具能力从实际命令结果确认。查询官方知识时先搜索，再读取返回的真实文档地址；文档服务不可用时改查官方网页。IDE 集成不可用时，继续使用项目命令与其他现有工具，不以此阻塞独立工作。
- 使用官方技能目录查询本次需要的专项技能，优先复用已安装项；安装或更新遵守本次授权，不默认安装全部。官方技能保持原稿，我们自己的补充写在本平台规则或项目规则中，避免官方更新覆盖。
- 构建和测试使用当前仓库的 Gradle Wrapper 与已核实任务。识别构建产物可用本机支持的 `android describe`，但应先检查其执行方式：工程分析可能调用 Gradle、解析依赖并生成文件，不能当作无副作用的文件列表查询。只读参考端不因此自动执行 Gradle。
- 部署前确认目标设备、包和产物属于本次项目；用实际产物元数据确定 APK，不猜路径或安装陈旧包。设备操作前读官方交互参考；UI 验收按任务保存布局、截图及实际交互证据，性能任务保存对应分析证据。
- 缺少设备、依赖、服务或工具时分项标明实际状态；工具安装成功不等于 App 构建、运行或验收成功。CLI 不可用时使用已核实的 Gradle、ADB 等现有工具，明确未覆盖能力；不自动升级项目工具链或下载无关 SDK。
