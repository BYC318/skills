# iOS 双端协作补充

本文件只供从双端协作入口开展 iOS 任务时读取，位置在双端协作根目录。它是按路径读取的项目约定文件，不是自动加载的特殊文件名，不替代或复制源码仓库已有的规则和技能。

## 读取顺序与维护边界

1. 从 [双端项目说明.md](双端项目说明.md) 找到本端实际源码仓库、Git 根目录和技能目录；未绑定时不猜选工程。
2. 先逐级读取源码仓库 Git 根目录到目标目录的既有规则，每级优先 `AGENTS.override.md`，否则 `AGENTS.md`；非 Git 工程从约定根目录开始。
3. 读取本文件中适用的补充说明；按任务选择当前会话已发现的根补充技能及源码仓库 `.agents/skills/` 中的技能。已发现的根补充技能不要求在本文件重复列索引，仅在固定使用、选择有歧义或不在发现范围时补充必要指引。源码端已有索引可利用，没有时按需检查技能名称和描述，不要求新增索引。
4. 实际加载选中的 `SKILL.md` 和必要资源，资源路径以所属技能目录为基准。用户级或插件能力先核实可用性；下面的候选名称不代表已安装，不全量加载或安装。

双端初始化和配置更新默认只读源码端 Agent 配置，不新增、修改、删除或搬动其 `AGENTS.md`、`AGENTS.override.md`、`.agents/` 或技能。需要补充的双端说明维护在本文件；技能缺失记录在双端目录，不自动给源码仓库补配置。只有用户明确要求修改该端配置时另行处理。

本端同事仍使用仓库已有入口，无需读取本文件。已有源码规则继续适用，本文件不用于绕过它们；约定冲突且影响任务时说明冲突，先解决再执行。派生工程师 Agent 时明确传入本文件及实际源码规则、技能路径，不能假设自动继承。

## 工程取舍

从双端入口实现 iOS 任务时，按 [工程取舍与改动边界](.agents/skills/dual-platform-workflow/SKILL.md#工程取舍与改动边界) 判断复用、适配或新写，保留本端架构与风格。异步回调、视图复用和生命周期变化可能使先前条件失效，保留有依据的检查与错误处理，避免逐层重复防御。上述是结合工程判断的默认原则，源码适用规则和平台契约继续遵守。代码修改使用可用的 `commenting-business-intent`；关键不确定或版本敏感的技术决策核实对应官方依据，区分平台契约与推荐实践。

## 执行能力


iOS 任务先区分工程资料核对、代码实现和运行验收。由 Codex 根据任务选择现有技能，用户不必提供技能名。纯 iOS 任务可以直接使用对应技能，不必建立双端记录。

| 任务信号 | 按需加载的能力 |
| --- | --- |
| Swift／Objective-C 实现、重构、审查或诊断 | `ios-engineering-guide`；修改代码同时使用 `commenting-business-intent`，Swift 文件使用 `swift-code-standards` |
| UIKit 布局、safe area、RTL | `uikit-layout-standards`；远程页面另用 `remote-page-development`，资源任务按工程是否采用 R.swift 选择 `rswift-resource-references` |
| SwiftUI 页面、状态和拆分 | `build-ios-apps:swiftui-ui-patterns` 或 `build-ios-apps:swiftui-view-refactor`；Liquid Glass 按部署版本与需求选择 |
| 构建、测试、模拟器运行与调试 | `prefer-local-spm-cache` 与 `build-ios-apps:ios-debugger-agent`；实际工具入口优先 XcodeBuildMCP |
| 卡顿、启动慢、内存增长 | SwiftUI 任务可用 `build-ios-apps:swiftui-performance-audit`；需要采样或泄漏证据时选 `build-ios-apps:ios-ettrace-performance` 或 `build-ios-apps:ios-memgraph-leaks` |

- 先复用当前可发现的技能，不全量加载。缺少专项能力时查找维护来源、适用范围和依赖，按任务授权补齐；不把第三方插件称为 Apple 官方技能，也不为凑齐能力安装无关工具。技能存在不代表其执行依赖已经可用。
- 从当前工程核对 workspace/project、scheme、configuration、部署目标、Swift／Objective-C／UIKit／SwiftUI 使用情况、包管理入口和锁文件。共享框架按实际入口处理；不把某 App 的架构、Pods 版本或模拟器架构例外推广到其他 App。
- 在第一次构建、运行或测试前读取 XcodeBuildMCP 的 `session_show_defaults`，核对工程、scheme、目标设备及产物路径；其他聊天或上个 App 的会话默认值不能作为依据。当前目录未绑定 App 时，只检查本机工具能力，不猜选 App 或发起构建。
- 优先使用可满足当前约束的 XcodeBuildMCP 工具。先核对当前工具 schema；旧技能中的工具名、参数或示例与实际接口不一致时，采用实际可用接口。工具无法指定所需产物路径时，改用显式路径的 Xcode 命令、`simctl` 或已安装的 `sim-use`，不能为了使用插件绕过路径要求。
- 构建前确定本次产物目录，显式配置 DerivedData、SourcePackages、包缓存、结果包及日志路径，截图、录屏、性能记录也放在获准目录。具体磁盘路径由当前用户和机器规则决定，不写死在本平台规则；指定卷不可用时停止相关动作。包依赖优先复用已有缓存，缺失时按已有技能联网补齐；保留锁定版本，不自动升级依赖或改签名设置。
- 多台模拟器运行时显式选择本次目标；仅探测工具能力时不启动、退出或操作已有 App。部署时从本次构建产物核对 Bundle ID 与设备架构，再安装、启动并检查运行结果；旧安装包、现有进程和截图不能证明当前代码已生效。
- UI 验收结合最新界面结构、截图和实际操作，分别核对布局、RTL 方向、点击区域和业务结果。卡顿／泄漏结论需要对应场景的采样或所有权证据；模拟器通过不代表真机、签名、推送、第三方登录或真实性能已验证。
- 性能工具需要临时接入或应用侧 instrumentation 时，先明确影响范围；遵守该工具的使用和清理流程，不自动给所有工程添加依赖。分别记录“技能可发现／工具可调用／本次场景已验证”，未测的能力不写成通过。
