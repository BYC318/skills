# 双端协作入口

## 项目资料与职责

本目录维护一个 App 的双端协作资料，也可以作为未绑定模板。任务和文档默认使用简体中文。先读 [双端项目说明.md](双端项目说明.md)，按本次任务确认工程与各端角色；不要从历史聊天猜选 App，不把空目录当作已接入工程。

日常开发、移植、差异核对和任务接续使用本项目的 [双端协作技能](.agents/skills/dual-platform-workflow/SKILL.md)，不调用用户级初始化技能。仅用户主动要求初始化或更新协作配置时使用 `dual-platform-development`。本说明不会自动关联 Codex 源文件夹。

## 各端规则与技能读取约定

按本次涉及的平台，明确读取根目录的 [iOS 协作补充](AGENTS_iOS.md) 或 [Android 协作补充](AGENTS_Android.md)。两者是本入口指引读取的普通文件，不会因命名自动生效；各端工作依次读取源码既有规则、对应根补充和按需选中的技能。派生工程师 Agent 时也传入这些路径。

- 平台工程、源码仓库、Git 根目录、规则入口与技能索引以项目说明中的已核实位置为准，相对路径从项目说明所在目录解析。`未绑定`、`待核对` 或不存在的路径不可执行。
- 开始某端工作前，按实际路径检查该端从 Git 根目录到目标目录的规则；每级优先 `AGENTS.override.md`，没有时读 `AGENTS.md`。非 Git 工程从约定工程根目录开始，目标范围变化时补读规则。
- 已有技能索引可利用；没有时只检查该端 `.agents/skills/` 的名称和描述，再按任务加载适用 `SKILL.md` 和必要资源，不全量加载。技能资源相对路径从该技能目录解析。索引不是前置要求，不为补索引改写源码端规则。技能缺失或不可读时在双端目录记录实际缺口，不能声称已加载。
- 双端初始化或配置更新默认只读源码端 Agent 配置，不新增、修改、删除或搬动各端的 `AGENTS.md`、`AGENTS.override.md`、`.agents/` 或技能。补充说明维护在根平台文件；只有用户明确要求修改源码端配置时另行处理。
- 根 `.agents/skills/` 保存双端协调能力及本协作入口使用的个人补充技能，包括 iOS、Android 专项能力。源码仓库既有平台技能保持原位，按路径复用，不复制、镜像或建立软链接。已有共享能力按来源引用，不把本机安装视为所有同事均可用。
- 已被当前会话发现的根补充技能，按名称、描述与任务选择，不要求在 `AGENTS_iOS.md` 或 `AGENTS_Android.md` 重复列索引。需要固定使用、消除选择歧义或补足发现范围时，再提供必要的读取指引；选中后读取正文和必要资源。
- 自动发现不等于按路径读取；不能假设当前会话会向下扫描平台技能、跨独立仓库继承本入口，或因 shell 切换目录就自动重载规则。各端仓库独立使用时不依赖双端目录。

## 可选的独立 Codex 任务协作

仅当用户主动点名 `$codex-task-coordination`、明确要求使用该技能，或明确继续此前已启用该技能的协作任务时，读取 [项目任务协作配置](任务协作配置.md) 和 [独立任务协作技能](.agents/skills/codex-task-coordination/SKILL.md)。启用后按其长期任务、通信、恢复及集中集成协议执行；本轮正常接续无需重复点名。普通开发、UI 对齐、已有任务目录及初始化安装均不自动启用。

该技能管理侧边栏中独立聊天的长期推进；下文规则管理各聊天内部的 Agent 分工，两层可以同时使用。每个独立任务可按工作量直接执行或派生子 Agent，所属聊天负责汇总结果和对外交付；内部委派不扩大其跨聊天职责或源码范围。仅维护配置或移植技能不创建真实任务、不发送协作消息，也不继承其他项目的聊天 ID、运行记录或授权。

独立聊天统一用“双端协调、端内协调、模块执行”区分角色，多级结构按[协调层级协议](.agents/skills/codex-task-coordination/references/hierarchical-coordination.md)按工作量启用：可省略端内协调聊天，各组只协调直接参与者，跨组逐层转述；每个真实仓库目标交付线指定唯一集成负责人，上层核对汇总而不重复集成。原有验收、源码归属及各聊天内部派生规则继续适用。源码 worktree 从启动时各仓库的当前分支快照创建，最终 rebase 跟上该分支最新进度并快进回写，详见 [分支基线与集成规则](.agents/skills/codex-task-coordination/references/code-delivery.md)。

共享任务按[两类共享任务的职责与触发条件](.agents/skills/codex-task-coordination/SKILL.md#共享任务的职责与触发条件)设置，可以为零；不默认按“iOS＋Android＋共享任务”拆分。仅跨端行为或契约一致由协调主任务对齐，各端实现仍归各端任务；登记真实公共来源后再选择仓库内提交接入或跨仓库依赖交付。

## 执行与验收边界

- 单端独立开发由对应源码仓库自身的 Agent 配置决定；未采用独立聊天协作且两端工作均属于当前聊天时，按本地协作技能判断是否派生 iOS 和 Android 工程师 Agent，由当前聊天主 Agent 协调并验收。已采用独立聊天协作时，不再为其他聊天已分配的源码重复派生执行者；当前聊天内部仍按自身范围选择直接执行或派生子 Agent。小改动、只读核对或依赖紧密时，由所属聊天主 Agent 在自身范围直接执行。
- 编码权限按实际职责和源码归属判断。单 Agent、模块或共享任务内部主 Agent，可以在自身授权范围直接编码、修复、构建、测试和取证，也可按工作量派生子 Agent。多 Agent／多独立任务中的协调者不接管已分配给其他执行者的源码，限制只作用于其协调范围；明确留给自己的独立工作仍可执行。调整已分配范围前，先核对在途动作和工作区，确认原执行者停止相关写入并记录职责交接。执行者不可用不自动转移归属，公共代码唯一维护及实际授权继续遵守。
- 派生时明确传入各端实际路径、适用规则与技能位置、契约、文件边界、验收项和验证约束；不得假设子 Agent 已继承平台规则或完整的技能列表。
- 以业务正确为前提，保留项目架构与风格，按开发、迁移、维护、性能和验收总成本选择复用、适配或新写，减少无关改动、空壳抽象和重复防御，保留有依据的边界与错误处理。涉及方案取舍时读取 [工程取舍与改动边界](.agents/skills/dual-platform-workflow/SKILL.md#工程取舍与改动边界)，按当前工程判断，不按行数、调用次数或类型名称机械裁决；实质取舍才简要说明依据。
- 代码任务使用可用的 `commenting-business-intent`；涉及复用取舍时按需使用 `reuse-before-building`。平台专项能力由各端规则和技能指导，关键且不确定的技术决策查官方依据。
- 存在 `.codegraph/` 时先用 CodeGraph 理解或定位代码，否则不自行索引。Git 操作明确实际仓库；同一 Git 根目录共享状态，由主 Agent 协调。
- 构建、运行与证据产物遵守用户、当前机器和目标仓库约束，执行前核对实际工程、工具会话及设备。只读参考不自动构建，未绑定不猜选 App；工具可用、构建通过与业务验收分别记录。

## 任务接续与配置维护

需要跨聊天接续时，使用本地协作技能附带的 [任务记录模板](.agents/skills/dual-platform-workflow/assets/双端任务记录模板.md)，保存到 `任务记录/<任务名称>.md`。采用独立聊天协作时，先按该协议恢复长期聊天、批次和未关闭依赖，再核对当前工程、Git 及聊天内部的执行进度；内部子 Agent 可按需重新派生，不把其标识当作长期聊天身份。未采用时直接按项目记录接续，不把历史快照当成当前事实。

更新配置保留已有规则、定制和历史记录，按语义合并，不重复追加入口或创建技能副本。缺失资料只追问阻塞本次工作的信息。提交、推送、PR、发布和外部回写遵守用户当前授权。
