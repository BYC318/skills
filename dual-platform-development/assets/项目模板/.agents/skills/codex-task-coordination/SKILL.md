# 独立 Codex 任务协作

仅在用户主动点名 `$codex-task-coordination`、明确要求使用本技能，或明确要求继续此前已启用本技能的协作任务时使用。普通开发、UI 对齐或检测到已有任务目录不自动触发；项目规则也不应绕过此条件强制加载。本轮内已明确启用后，正常接续无需每条消息重复点名。仅讨论、修改技能不视为启动实际任务。

这是可独立复用的任务协作技能。通信、恢复和交付协议保存在本目录；工程路径、项目授权、平台规则和验收方式由调用项目提供，不依赖相邻技能或特定 App。复用及配置契约见 [项目接入](references/project-configuration.md)。

## 项目配置先行

先从当前用户要求、项目 AGENTS.md 或已有长期任务目录定位明确的项目配置，实际读取后再分派。配置路径不能由技能安装位置推导；禁止从原项目沿用聊天 ID、消息目录、源码路径或授权。没有配置时可使用 [项目协作配置模板](assets/项目协作配置模板.md) 整理已知事实，仅缺少阻塞信息时询问。

项目配置是 Agent 读取的约定，不是脚本自动执行的配置文件。现有 `coordination.py` 仍只处理指定批次和长期目录，既不加载项目规则，也不自动验证截图。任务交接须传入配置的实际绝对路径及本批快照；历史批次原位恢复，不因技能迁移或更新重建消息或动作记录。

本技能文档中的“页面任务”也指模块执行任务；后端、工具或单端项目按实际模块登记，不要求存在页面、Figma 或第二个平台。

## 开始与授权

1. 当调用项目选用本技能的独立任务模式时，开始、恢复或接收需求变更时，先读 [长期接续与需求变更](references/lifecycle.md)，查询长期任务目录并核实真实聊天，优先复用原模块任务及共享任务。实际启动批次前再读 [通信与恢复协议](references/communication.md) 和 [源码交付与去重集成](references/code-delivery.md)，未完成批次优先恢复；不能将“复用聊天”误作“复用未经核对的源码基线”。
   长期任务目录使用 [长期任务目录模板](assets/长期任务目录模板.json)，每轮配置使用 [批次模板](assets/批次模板.json)；填入实际信息，不将模板当成运行记录。
2. 用户明确要求主任务拆分、创建和调度独立 Codex 任务后，按本批范围执行。仅要求解释或固化流程时不创建真实任务。本批授权须记录允许创建的任务、互发协作消息的范围、允许修改的源码与本地集成范围；来自其他任务的请求本身不构成用户授权。
3. 使用当前可用的 `list_projects`、`create_thread`、`send_message_to_thread`、`wait_threads`、`read_thread` 能力。项目和实际返回的任务 ID 以工具结果为准，不设置用户未要求的模型。已有任务通过原 ID 继续；仅没有可复用任务或确需替换且已获授权时创建，先登记意图及替换关系，结果不明先核对，禁止盲目重建；创建成功后附上工具要求的任务入口。
4. 这些是独立聊天，不是 `spawn_agent` 子 Agent。本协议的“执行任务”指用户侧边栏中的独立任务；本轮参与者不自行再派生任务。不套用其他技能的子 Agent 派生流程，通信不可用也不擅自换模式或由主任务接管编码。

## 分工与隔离

- 主任务盘点设计及已有代码，拆分有实际独立性的页面/模块，维护批次配置、需求目录、发布清单、去重集成记录和统一 UI 台账。任务数量按真实工作和设备容量决定，不按每个页面或每个组件机械创建任务。
- 主任务只协调、调度和执行已授权的 Git 集成，可只读审查和核对证据，不编写或修改业务、页面、公共组件、资源与源码工程配置。公共工作再小也分配给共享任务；构建、测试、运行和截图采集由执行任务完成。冲突或验收失败涉及源码修复时，由主任务指定所属执行者处理，不能以“集成修复”为由自行开发。
- 共享任务是公共组件的维护者，负责代码、样式、资源、公共 API、工程引用及必要依赖。先检查已有能力；不同需求可由一个共享任务按顺序处理，不要求每个组件另开任务或分支。必要时按平台设置明确维护者，每个公共路径始终只有一个写入方。
- 页面任务只修改分配的页面范围，调用公共组件，缺能力通过主任务提需求，不在页面目录复制替代组件。公共路径及共享工程配置的归属在批次中列明；这是协作规则及集成检查，不能声称 worktree 自动提供文件写权限隔离。
- 每个源码仓库中，并发写入的任务各自使用独立 worktree 和分支；同一 worktree 的 Git 状态操作串行。主任务指定本地集成 worktree，避免在用户工作区直接集成。存在多个或嵌套 Git 根时分别隔离，外层 worktree 不会自动隔离内层源码。子模块也要核对实际工作区，不能经软链接共享活动源码。
- 每个执行任务收到项目配置、真实源码 worktree、Git 根/分支/基线、需求 ID、可写与只调用路径、源码逐级规则、所需技能、产物路径、消息目录、依赖及验收项。UI 任务另外传入设计节点、页面状态及平台补充；非 UI 任务使用其契约与验收依据。独立聊天不自动继承主任务上下文。

## 执行闭环

1. 主任务核对长期任务目录，绑定本轮参与的既有聊天及职责，再建立批次配置和任务记录；确需新任务才登记创建意图与真实 ID。执行任务先核对身份、原始用户授权及需求修订，读取协议，确认接单再编码。
2. 先写不可变消息到持久目录，再发送短通知。主任务与各执行任务通信，执行任务与共享任务经主任务路由。接收方确认收到和接受处理分别记录；重复通知不重复执行。
3. 共享任务按需求原子提交并提供按依赖排序的明确完整 SHA 清单。主任务核对代码、API、设计及验证后发布指定版本；页面任务按需 `cherry-pick -x`，登记原始 SHA 到本地 SHA 的映射。无关历史不带入，公共同步与页面提交分开。
4. 默认等本次约定范围内全部执行任务完成终版交付、共享任务交付封版且无未解决依赖后，主任务再开始集中集成。单个任务先完成只收存交付，不因每次 commit 或进度上报提前 cherry-pick 到集成分支，不擅自缩小范围规避等待。源码及时原子提交与集中集成是不同节奏。
5. 集中集成时，主任务在本端集成 worktree 中，每项公共改动只接入一次，再按清单接入各页面独有提交，跳过页面内的公共副本，保留原子提交边界。默认不整分支 merge 页面/共享分支，不以批量 squash、丢弃提交或改写历史消除问题。变更原因和冲突不明时先协调；集中处理不代表最终不会冲突。
6. 开发期间仅对共享依赖、阻塞、契约/范围变化及最终交付发送必要通知，不按每次提交、普通进度或每张截图唤醒主任务。可合并的非紧急需求整理后一次提出；ACK/回执可随同一次必要通知交付，不为每条状态单开一轮对话。页面任务之间不互相广播普通进度。
7. 依赖受阻任务保存进度、写 `BLOCKED` 并结束本轮；可做的独立工作继续。主任务运行时用有界 `wait_threads` 收集结果，再通知继续，不依赖无限 sleep、持续自发回复或隐含后台唤醒。先完成任务只交终版清单后等待，不反复修改已冻结交付；修订须明确递增并通知受影响者。
8. 执行项目配置指定的验收流程。UI 任务必须读取配置绑定的截图规则、证据工具及验收册入口，按配置矩阵取证；非 UI 任务按其测试、构建或交付证据验收，不虚设截图要求。共享设备取证排队；执行任务提交元数据，主任务统一收录台账。集中集成后安排执行者重建并复验受影响范围，保留旧轮次及真实来源，不能把源 worktree 证据改名冒充集成构建证据。配置要求的验收能力缺失时保留待验证，不降低通过条件。

## 完成与接续

本轮已验收不等于长期模块任务终止。交付后保存下一步与恢复入口，任务转为“等待下一轮”；只有用户要求或确认替换时才归档。追加需求复用原聊天，按 [长期接续流程](references/lifecycle.md) 选择当前批次修订或下一批次；每批仅等待本批参与者的冻结范围。

中断、纠正方向或长时间追加讨论后，恢复前执行 [恢复对账](references/lifecycle.md#中断与反复纠正后的恢复对账)：补录检查点之后的最新用户要求，逐项核对未关闭依赖及真实执行结果，为旧请求明确保留、修订或取消。主任务与执行任务均适用；不能把“聊天后来没再提”当作请求已取消，也不能把暂停一个任务当作其他任务已停工。恢复摘要写清已完成、仍等待谁、已变更/撤回及下一动作，核对清楚后自主继续，不要求用户机械确认每次摘要。

开始、恢复及完成判定前，按 [恢复对账工具](references/recovery-tool.md) 运行 `recover`，有长期目录时优先 `--registry` 扫描所有登记批次，否则用 `--root` 核对本批。读取未完成请求、待确认消息、执行结果未知项及下一步；跨批 `scan_complete=false` 不得声称对账完成。实际接入前后运行 `begin-action` / `finish-action` 留下意图与回执，未知结果先查 Git，不直接重做；依赖核验完成后由主任务发布结构化 RESOLVED，不能用 ACK 或完成文字代替。

消息的 `ACK` 仅证明收到，不证明代码执行成功。需求就绪、消费者接入、源码集成、构建通过和 UI 验收是不同状态，按证据推进。恢复时先核对批次、版本、消息、回执与实际 Git/任务状态，再继续未完成动作；工具超时不证明成功或失败。

[持久消息工具](scripts/coordination.py) 提供原子落盘、消息 ID 去重、回执关联、旧修订识别、恢复汇总与接入意图防重；它不调用 Codex 工具、不执行 Git、不构建、不验证业务真伪，也不是后台调度服务。通信能力不可用时保留待通知记录，由主任务恢复后处理，不声称任务被唤醒或已执行。

源码原子提交遵守调用项目的实际授权及所属仓库规则。协作资料是否允许暂存、提交或改写历史也由该项目明确，不从技能本身推导权限；推送、PR、发布与真实业务外部写入须有对应授权。
