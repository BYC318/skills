# 工作区目录与聊天、分支对应

本页在规划、创建或恢复独立聊天及源码工作区时读取。目录组织用于让用户找到实际工作区，不改变[分层职责](hierarchical-coordination.md)、[共享任务条件](../SKILL.md#共享任务的职责与触发条件)或[集成工作区选择](code-delivery.md#集成工作区选择)。

## 目录组织

新任务的 `worktree/` 与原源码仓库工作区并列，先按真实源码位置确定父目录，再在该父目录下使用 `worktree/<需求简称>/<平台>/<任务目录>/`。它不固定属于 `test/`、协作配置目录或技能目录。两端原源码仓库同父目录时共用这个并列的根；父目录不同时，分别登记各仓库同级的 worktree 根，不为凑一个根搬动源码或猜选更高层公共目录。项目配置中的显式相对路径仍按声明的项目根换算，实际命令和运行记录使用核实后的规范绝对路径；不能把源码位置推导出的根误解为协作目录下固定的 `worktree/`。已有明确的项目路径定制保留，并向用户展示逻辑目录与实际路径的对应关系；没有既有约定时，不默默把源码 worktree 放到另外的临时产物目录。

两端原源码仓库恰好同父目录时的完整结构示例：

```text
源码仓库所在父目录/
├── iOS/                         原源码工作区，按实际项目路径保留
├── Android/                     原源码工作区，按实际项目路径保留
└── worktree/
    └── 需求简称/
        ├── iOS/
        │   ├── iOS总协调/        协调入口，源码工作区优先安全复用
        │   ├── iOS子模块任务_登录/
        │   ├── iOS子模块任务_首页/
        │   └── iOS共享任务/      实际需要时才建立
        ├── Android/
        │   ├── Android总协调/    协调入口，源码工作区优先安全复用
        │   ├── Android子模块任务_登录/
        │   ├── Android子模块任务_首页/
        │   └── Android共享任务/  实际需要时才建立
        └── 双端共享任务/         实际需要时才建立
```

图中的父目录、源码路径、需求和模块名称均按调用项目实际情况替换；只有原源码仓库本来就在 `test/` 下时，这个并列目录才是 `test/worktree/`。已有工程路径保持原样，不改名为示例的 iOS/Android。层级按工作量启用，只创建实际参与的平台、协调层和执行任务。三类共享目录与聊天均按需创建，不为展示完整结构预建空目录、空聊天或占位分支。已有同角色公共来源需区分时，目录名追加实际范围。

源码仓库的父目录、`worktree/`、需求及平台目录通常是组织目录；模块目录和已启用共享任务的源码目录才须核实为所属真实仓库的 Git worktree。协调目录可以只是资料入口，也可以不另建而引用既有入口；纯协调聊天可以没有源码工作区，不能把普通目录算成源码 worktree。源码集成优先安全复用原目标工作区；仅确需隔离时在相应平台下增加候选集成目录，不为候选目录另开聊天。一个协调聊天可以管理目标和候选两个工作区，聊天数、目录数和 worktree 数分别统计。

跨仓库公共依赖任务围绕真实公共来源仓库建立 worktree；多个来源确需由同一聊天维护时，按仓库分别登记源码子目录和分支。一个“共享任务”目录不使两端原生实现成为同一仓库。仓库内共享消费者按审核清单准确 cherry-pick，共享交付和各仓库最终集成继续遵循原协议。

源码 worktree 根应位于各活动源码工作区之外，避免把模块 checkout 嵌入另一活动源码 checkout；同仓库或嵌套仓库按真实 Git 根核实位置。若默认位置不满足工程结构或项目限制，明确记录适用的实际位置及原因。构建、缓存、日志、截图和验收产物仍按机器及项目约束保存，源码目录布局不改变这些位置。持久批次、消息和回执沿用项目资料路径，不放进会切换或集成的源码 checkout，也不为统一外观搬移旧资料。

## 聊天与工作区如何登记

沿用长期目录的 `tasks.<逻辑ID>`，区分以下信息：

| 信息 | 登记位置及含义 |
| --- | --- |
| 真实聊天及职责 | `thread_id`、`host_id`、`title`、`scope`；标题按[窗口命名规则](hierarchical-coordination.md#独立聊天窗口命名)，真实 ID 不由目录名推断 |
| 任务资料入口 | `task_directory`：实际资料入口的规范绝对路径；未建立时为 null，可以与源码目录不同，不能据此认定已经创建 worktree |
| 源码工作区 | `workspaces`：逐仓库、逐用途登记实际工作区；纯协调角色可以为空，复用原目标工作区时填写其真实路径 |
| 每个工作区的最小信息 | 稳定 `repo_id`、`git_common_dir`、规范绝对 `path`、实际本地分支完整引用 `branch`、核实的起点 `start_sha`、用途 `purpose`、所属 `batch_id` 和最终 `target_branch`；最新 HEAD 作为实时核对结果记录，不覆盖起点 |
| 本轮仓库基线和集成 | `batch.json.repositories` 保存原源码工作区、`target_branch` 和固定 `startup_sha` 及各任务起点；`integration.json.repositories.integration_worktree` 保存实际累计结果的目录，关联 rebase 映射及每次目标回写 |

长期目录的 `worktree_root` 仅在共用一个根时记录实际规范绝对路径，未建立或各仓库分属不同根时为 null；多个根按 `repo_id` 在批次 `repositories` 逐仓库记录 `worktree_root`，各聊天的 `workspaces.path` 始终填写实际源码工作区路径。`task_directory`、`worktree_root` 以及 `workspaces` 条目是 Agent 维护的可选元数据；旧目录缺失时按原记录恢复，不为补展示字段重建批次或改写事件。脚本不会自动创建这些目录、绑定聊天环境或验证 Git 对应关系；空值不代表就绪。

实际创建或绑定后，在聊天接单说明及主任务记录展示一份可查对应表，至少包含“聊天标题/真实 ID、任务资料入口、实际源码 worktree、仓库/用途、工作分支、启动基线、最终目标分支”。同一聊天对应多个源码工作区时分别列行；省略角色不造空行，纯协调无源码时明确填写“无源码工作区”。目录名可省略需求简称，因为上层已包含；不能将聊天标题中的模块名换成含糊的 A/B。

目录存在、Git worktree 建立成功、聊天执行环境正确是三个核对项。用真实 Git 的 worktree 列表、公共对象库身份、symbolic HEAD 和 HEAD 验证实际路径、附着分支及提交，并核对聊天工具实际绑定/使用的工作目录；无法确认正确执行环境时保留待绑定，不假报已在指定 worktree 开发。分支命名遵守项目规则，记录完整引用，不要求分支名称与中文目录同名，也不为展示方便重命名既有目标分支。

### 从真实登记导出汇总

创建工具回执核实后，先更新本组长期目录 `tasks` 的真实 ID、标题和工作区，再用只读入口生成对外映射：

```bash
python3 '技能脚本的绝对路径/coordination.py' task-map --registry '本组长期目录的规范绝对路径.json'
```

输出从 `tasks` 投影实际登记字段并附 `registry_file_sha256`；汇总中的 `children` 从其中除 `main_task_id` 外的任务取值，不再复制创建计划。缺少聊天 ID/标题或同组重复绑定同一聊天时拒绝导出，先查真实创建回执，不能补造身份。纯协调者的 `workspaces` 可以为空，旧目录缺展示字段时先核实补记，原 `recover` 不因此受阻。

此入口不查询聊天或 Git，`recorded_status` 仅为登记状态，`live_state_verified: false` 不可改报实时已核验；当前状态仍按上文的真实工具和 Git 依据核对。创建绑定后及最终交付时按需导出，不给每条消息增加全组扫描。已冻结汇总保持原样；发现登记遗漏时修正长期目录并生成新映射/接续补充，不覆盖旧交付及其哈希。

## 创建、冲突与接续

- 创建前按仓库登记启动时当前目标分支和 HEAD，再从该固定起点建立各模块及仓库内共享分支/worktree；同仓库的并行执行者各用独立工作区。目录规划不替代 `git worktree` 的真实建立及核验，也不因建立同一个外层目录就隔离了嵌套源码。
- 路径已存在时先核对登记记录、仓库身份、工作分支及在途动作；确认归属、当前批次基线和交接均匹配且可安全使用时复用，否则明确列出冲突，不覆盖、清理、改名腾位置或把普通文件夹当成已初始化 worktree。确需并存新一轮工作区时，在需求或任务目录追加可读的批次标识并登记前后关系，不移动旧目录。不得通过软链接把不同聊天指向同一份活动源码来冒充隔离。
- 源码仓库与其同级 worktree 的目录树、实际任务图及 worktree 对应表在创建/绑定后和最终交付时展示；写清原目标、执行和按需候选工作区。只完成文件系统 Git worktree 操作，不等于已注册为应用内托管工作树或已绑定聊天，报告分别依据实际工具回执说明。
- 复用聊天或更新需求简称时，保留原真实 ID、旧路径及分支历史；不因标题变化自动移动 worktree。恢复沿用已核实登记的实际路径及原源码工作区关系，不从当前聊天 cwd、派生模块 worktree 或新标题重新推导根；旧登记缺失时先核对原入口和真实 Git，不猜选目录。新一轮是否复用源码工作区按基线及交接规则判断，需要新路径时记录前后关联。已有演练和历史批次原位保留，不为了新布局迁移或重做已完成动作。
- 协调工作区和最终回写继续按[两种集成流程](code-delivery.md#集成工作区选择)选择；目标分支身份不变但可持续推进，终版共享及模块交付 rebase、去重、复验后快进回写。不得通过目录布局放宽源码归属、在途写入交接、暂存区保护或用户授权。

仅维护或同步本技能时，只更新配置与模板，不创建示例目录、真实 worktree、聊天、活动分支或运行批次，也不搬移现有工作区。
