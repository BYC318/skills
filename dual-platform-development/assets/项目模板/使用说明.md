# 双端开发使用说明

本目录负责协调已有 iOS、Android 工程；各端仓库继续支持同事独立开发。尚未绑定时只作为模板，不代表已经接入或验证 App。

## 三份技能的职责与触发条件

| 技能 | 负责什么 | 何时使用 |
| --- | --- | --- |
| `dual-platform-development` | 初始化或更新双端协作入口、项目说明、技能与模板；只维护配置，不开发或构建 App | 用户主动要求初始化、更新或维护协作配置时使用，配置完成后停止 |
| [dual-platform-workflow](.agents/skills/dual-platform-workflow/SKILL.md) | 日常双端开发、跨端参考、共同契约、任务内 Agent 分工、验收与接续 | 从双端入口开展相关任务时按需使用，无需每次点名 |
| [codex-task-coordination](.agents/skills/codex-task-coordination/SKILL.md) | 较大需求的长期独立聊天、模块归属、需求修订、批次、持久通信、交付、集中集成与恢复 | 用户主动点名、明确要求使用，或明确继续此前已启用的协作任务；正常接续无需重复点名 |

初始化技能部署或更新项目本地能力，日常开发直接使用本地配置与 `dual-platform-workflow`。启用 `codex-task-coordination` 后，它负责跨聊天推进，`dual-platform-workflow` 继续指导每个聊天内部的执行，两者可以同时使用。普通开发、UI 对齐、已有任务目录或技能安装不会自动启用独立任务协作；仅讨论或维护技能不启动真实任务，实际创建、通信与集成遵守用户授权。

## 初始化与更新

用户主动调用：

> 使用 $dual-platform-development 初始化这个 App 的双端协作配置。

或：

> 使用 $dual-platform-development 更新协作配置，保留已有项目规则与各端技能。

配置维护按语义合并，不覆盖定制或清理个人补充技能；再次更新不追加重复规则或技能副本。仅缺失且阻塞当前配置的信息需要补问。工程未指定时保持未绑定，不猜用历史 App。

## 三个入口与技能维护位置

| 使用者 | 工作入口 | 平台能力来源 |
| --- | --- | --- |
| 双端开发者 | 双端协作目录 | 结合根补充技能，按实际路径读取两端既有规则和技能 |
| iOS 开发者 | iOS 源码仓库 | 本仓库规则及 `.agents/skills/` |
| Android 开发者 | Android 源码仓库 | 本仓库规则及 `.agents/skills/` |

根 `.agents/skills/` 可以保存双端协调能力和你为本协作入口维护的补充技能，包括 iOS、Android 专项能力。源码仓库既有平台技能保持原位，按路径复用，不复制、镜像或建立软链接。单端仓库无需依赖双端目录。各端仓库可位于外部位置，不要求搬到固定目录或改名为 `iOS`、`Android`。

已被当前会话发现的根补充技能，按名称、描述与任务选择，不必在 `AGENTS_iOS.md` 或 `AGENTS_Android.md` 逐项登记；仅在需要固定使用、消除歧义或补足发现范围时写读取指引。规则文件保留必要的长期约定，技能承载按需使用的方法与资源。

### 双端任务如何读取各端配置

各端配置仍由源码仓库维护，双端任务按实际涉及的平台读取并纳入上下文；单端独立开发由本端 Agent 配置决定。

1. 从 [双端项目说明.md](双端项目说明.md) 确认实际工程、源码仓库、Git 根目录及本次各端角色，未绑定或不存在的路径不作为执行目标。
2. 从源码 Git 根目录到目标目录逐级读取适用规则，每级优先 `AGENTS.override.md`，否则读取 `AGENTS.md`；非 Git 工程从约定工程根目录开始，范围变化时补读。
3. 读取双端根目录对应的 [iOS 补充](AGENTS_iOS.md) 或 [Android 补充](AGENTS_Android.md)，与源码适用规则一起作为本次协作依据。
4. 按任务选择源码端技能、根补充技能或其他可用能力，实际读取选中技能的 `SKILL.md` 和必要资源，纳入上下文并按适用范围执行。已有技能索引可利用，没有时检查名称与描述，不要求给源码端新增索引。

发现或匹配到技能元数据不等于正文已经加载；按路径读取也不等于自动注册，不能假设 shell `cd` 会重载规则。用户级或插件能力按实际来源和可用性引用，本机安装不代表同事已安装；缺失或不可读时明确标记，不声称已加载，不默认批量安装。

## 日常开发与接续

直接描述目标，例如“参考 iOS 给 Android 补齐收藏”“开发两端收藏列表”“核对两端差异”或“继续上次任务”。不再调用初始化技能；Codex 按本项目入口和本地能力开展工作，只询问当前缺失的必要信息。

两端工作独立且较大、契约和文件边界明确时，派生 iOS、Android 工程师 Agent，主 Agent 协调并验收。

当前聊天根据已分配工作的规模与依赖选择直接执行或派生子 Agent；启用独立任务协作后，每个模块或共享聊天仍可采用这两种方式。

- 单 Agent、模块或共享任务内部主 Agent 可在自身授权和源码范围内直接实现、修复、构建和验证，也可委派子 Agent；工具不可用时可继续自身尚未委派的工作。
- 派生时提供目标、实际工程与 Git 根目录、适用规则及技能路径、共同契约、允许修改范围、验收项、验证入口和产物约束，不假设自动继承上下文。子 Agent 返回改动、验证证据及阻塞，由所属聊天核对、汇总并对外交付。
- 多 Agent／多独立任务中的协调者负责调度、审查、证据核对、协作资料及已授权集成，不接管已分配给其他执行者的源码，明确留给自己的独立工作仍可执行。调整分工前核对在途动作和工作区，确认原执行者停止相关写入并记录交接；执行者不可用不自动转移归属，公共代码继续由指定共享维护者唯一负责。

保留现有项目架构与风格，按复用、改造和新写的整体成本选择，兼顾迭代、冗余、耦合、性能及验收成本。官方契约遵守，推荐实践结合项目采用；实质取舍才记录简短依据，不为小任务增加报告。

平台实现、构建和设备验证由各端规则及技能指导，遵守当前环境的产物路径和工程限制。只读参考不产生该端构建义务；技能可用、工具可调用、编译、模拟器、真机和业务验收分别记录。范围外平台不列为未完成开发。

持续任务使用本地模板记录进度与证据。恢复时核对当前工程、Git、证据、旧子 Agent 状态及在途写入；聊天中断不证明原执行者已停止，状态不明时不重复分配同一写入范围，确需替换时先停止或交接旧职责并记录替换关系。启用独立任务协作时，先按 [独立任务接续协议](.agents/skills/codex-task-coordination/references/lifecycle.md) 核对长期聊天、批次和未关闭依赖。提交、推送、PR、发布及外部回写遵守用户当前授权。

## 主动使用独立任务协作

需要长期保留主任务、模块任务及共享任务，分别追加需求和接续时，主动启用：

> 使用 $codex-task-coordination，按当前项目配置协调本次任务。

启用后先读取 [项目任务协作配置](任务协作配置.md) 和本地 [独立任务协作技能](.agents/skills/codex-task-coordination/SKILL.md)，核对实际仓库、授权与验收入口。

独立任务是侧边栏中可长期接续的真实聊天；子 Agent 是所属聊天的内部执行者，不替代长期聊天身份。真实聊天 ID 与子 Agent 标识分别记录，内部委派不扩大所属任务的源码范围或授权。

技能中的持久消息、需求修订、恢复对账和去重集成可跨项目复用；项目自行提供源码仓库、规则、授权、资料目录及验收条件。工程未绑定时保留待核对，不能创建实际开发批次。安装不携带其他项目的任务、聊天 ID、运行消息或授权，也不启动真实任务。消息工具适用于 macOS/Linux 本机共享存储；不提供跨机器通信或后台自动唤醒。

## 模板维护

初始化原稿位于用户级技能 `assets/项目模板/`，包括隐藏的 `.agents/`；使用技能名称定位，不在项目写死某台机器的用户技能目录。`AGENTS_iOS.md`、`AGENTS_Android.md` 维护双端补充，由根入口明确读取；默认只读源码端 Agent 配置，不给源码端新增索引或配置。

模板更新不会自动覆盖其他 App 的实例；用户主动更新时再合并差异，保留定制、平台维护位置和历史记录。初始化或静态检查通过不代表 App 构建或业务验收通过。
