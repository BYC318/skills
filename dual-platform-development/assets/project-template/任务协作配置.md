# 项目任务协作配置

本配置供 Agent 读取；仅用户主动启用 `codex-task-coordination` 或明确继续已启用任务时使用。当前工程未绑定，以下待核对项不构成授权；安装技能不创建真实聊天、长期目录或批次。

## 项目与入口

- 项目名称：未绑定。
- 项目根：`.`，相对本文件所在目录；以下项目路径均从项目根解析。
- 项目规则：[AGENTS.md](AGENTS.md)；工程与各端规则入口：[双端项目说明.md](双端项目说明.md)。
- 平台协调与验收依据：[双端开发流程](resources/references/dual-platform/工作流程.md)，按需读取对应平台补充和源码规则。
- 独立任务技能：[codex-task-coordination](.agents/skills/codex-task-coordination/SKILL.md)；运行不依赖初始化技能的安装位置。

## 仓库与权限

| 稳定仓库 ID | 实际路径 | 平台或职责 | 规则入口 | 本地提交授权来源 |
| --- | --- | --- | --- | --- |
| 待登记 | 未绑定 | 按实际参与平台或模块登记 | 从项目说明核实 | 待核实当前用户授权 |

- 跨聊天协调者负责调度、只读审查和已授权的 Git 集成，不接管已分配给其他执行者的源码；单 Agent、模块或共享任务内部主 Agent 可在自身授权范围实现、修复及验证。公共路径登记唯一维护者，调整已分配范围前先核对在途动作并完成职责交接。
- 创建聊天、互发协作消息、源码修改、提交及本地集成：实际启动前记录当前用户授权及边界；不能沿用其他项目授权。
- 协作资料是否允许暂存、提交、改写历史：待核实。
- 推送、PR、发布及业务外部写入：分别遵守实际授权。

独立任务内部可以由主 Agent 直接执行或按项目规则派生子 Agent；所属聊天汇总结果并对外交付，内部委派不扩大职责、源码范围或授权，也不替代长期独立聊天身份。

## 协调层级与集成归属（按需）

按 [多级独立聊天协议](.agents/skills/codex-task-coordination/references/hierarchical-coordination.md) 根据本轮工作量登记实际协调组、父子目录及批次绑定；不强制建立端内协调聊天或共享任务。每组维护自己的控制资料并逐层转述必要消息，每个真实仓库目标交付线指定唯一集成负责人；上层核对本端冻结交付，不重复执行已完成回写的同一目标线集成。接续分别扫描相关协调组、跨组映射及真实 Git，保留原有资料路径、授权及验收台账。本文件列出的资料路径为顶层／原单层默认约定；启用子组时分别登记其独立长期目录和批次路径，由父组 `children` 关联，不共写父组目录。

源码基线与最终集成按 [分支基线规则](.agents/skills/codex-task-coordination/references/code-delivery.md#启动分支开发基线与-worktree)：实际启动时逐仓库记录当前分支及启动 HEAD，模块和共享 worktree 从该起点创建；目标分支可持续推进，最终交付集中 rebase 到其最新状态并快进回该分支。批次保存实际快照和回写记录，本配置不固定活动分支。

## 共享维护与依赖（按需）

- 是否设置独立共享任务及触发依据：按[技能中的两类共享任务](.agents/skills/codex-task-coordination/SKILL.md#共享任务的职责与触发条件)判断；可以不设置，不因参与 iOS、Android 两端而默认增加角色。
- 设置时登记：仓库内共享代码／跨仓库公共依赖、权威来源的真实仓库与路径、唯一维护者、实际消费者、可写与只调用范围、接入方式和验证依据。各端适配归属分别明确，角色类型不扩大既有授权。
- 接入记录：同仓库公共原始 SHA → 各 worktree 副本 → 规范集成 SHA；跨仓库依赖则记录来源版本／哈希 → 消费仓库接入提交 → 本仓库集成及验证。仅契约对齐不创建共享代码任务；无本轮共享工作时不等待共享交付。

## 资料与接续

- 源码工作区根：按各原源码仓库真实位置确定，与源码仓库并列为其父目录下的 `worktree/`；同父目录可共用，不同父目录按仓库分别登记，不固定属于 `test/` 或本协作目录，显式相对路径按本配置声明的项目根换算。按[目录与对应规则](.agents/skills/codex-task-coordination/references/worktree-layout.md)组织需求/平台/任务；共享目录与聊天按需建立，协调工作区优先安全复用。实际运行登记规范绝对路径，原源码位置、既有运行目录及构建/证据路径保持各自约定，不因新布局自动迁移。
- 长期任务目录：待建立，建议项目内 `任务记录/独立任务目录.json`；正式使用登记真实聊天与历史批次。
- 新批次协调目录：待核对本机共享存储和项目产物约束，使用按项目、任务和批次隔离的实际绝对路径；不放在会被切换或集成的源码 worktree 内。
- 接续说明：实际启动后使用项目内 `任务记录/<任务名称>.md`，保留需求修订、未关闭依赖和下一步。
- 构建、日志及证据目录：遵守当前机器、用户与源码仓库规则，实际验证前核实；不在通用模板固定本机磁盘路径。
- 已有批次原位恢复；实际接续时核对配置快照、真实聊天、Git 及证据，不重建消息、执行意图或历史交付。

## 验收与配置变更

- 验收类型、参与平台、契约、验证入口和最终通过条件：待按本次任务明确；工程未绑定前不记为已就绪。
- UI 工作读取本地 [UI 对齐与截图证据流程](resources/references/ui-alignment/ui-evidence.md)，按实际设计来源和页面状态留存四组合证据，沿用统一台账；全量完成用 `deliver` 留存回执，接续或上级验收用 `verify-delivery` 复核，项目额外验收要求继续保留。非 UI 工作按契约、构建和测试验收，不强制截图或 Figma。
- 集成后由执行者复验受影响范围；共享设备串行使用，保留历史及真实来源，缺失条件记为未验证。
- 新批次登记本配置实际绝对路径并保存快照和哈希；变更时保留历史并核对受影响动作及证据。配置不包含密钥，也不是自动执行命令的脚本。
