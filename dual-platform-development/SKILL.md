# 双端项目初始化与更新

只负责建立或更新项目的协作配置。完成后停止，不自动进入功能开发、执行构建、派生工程师 Agent、克隆仓库、创建索引、安装工具或批量安装平台技能。日常开发使用项目自身的 `AGENTS.md` 和 `.agents/skills/`，不反向依赖本技能。

## 明确目标与核实工程

1. 用户主动调用后，区分初始化、更新已有配置或维护未绑定模板。先读取用户指定的资料、当前目录入口及项目说明；能从上下文和可见工程确定的信息直接核实，只询问阻塞当前配置的必要信息。不全盘搜索，不猜选历史 App。
2. 确定协作目录和各端实际工程、源码仓库根目录、Git 根目录及工程入口。工程可以位于外部路径，也可以同仓库；空目录、`未绑定` 和 `待核对` 不是工程接入证据。只核对现有文件和必要只读命令，不执行会解析依赖或生成工程文件的构建分析。
3. 对每个读取或修改目标，逐级检查实际 Git 根目录到目标目录的规则，每级优先 `AGENTS.override.md`，不存在时读 `AGENTS.md`；非 Git 目录从约定工程根目录开始。需要定位代码且存在 `.codegraph/` 时先用 CodeGraph，否则不创建索引。
4. 核实各端现有规则和技能入口，按实际需要读取技能元数据和引用。平台技能的维护位置保持在对应源码仓库的 `.agents/skills/`；已有用户级或插件能力可登记来源和依赖，不把本机可用误报成团队已安装。

## 生成或合并项目配置

按 [项目入口模板](assets/项目模板/AGENTS.md) 合并以下内容，已有文件先完整阅读，不用整目录复制覆盖项目：

| 内容 | 初始化或更新方式 |
| --- | --- |
| 协作目录 `AGENTS.md` | 合并项目入口及各端读取约定，移除要求日常开发加载本初始化技能的旧约定 |
| [双端项目说明.md](assets/项目模板/双端项目说明.md) | 登记已核实的工程、规则入口、技能目录及能力索引，不复制平台技能正文 |
| [使用说明.md](assets/项目模板/使用说明.md) | 说明用户主动初始化／更新与日常直接描述需求的区别 |
| [项目双端协作技能](assets/项目模板/.agents/skills/dual-platform-workflow/SKILL.md) | 合并双端协调技能及其本地任务记录模板；若已有同职责入口，优先整合，不再建立平行流程 |
| [AGENTS_iOS.md](assets/项目模板/AGENTS_iOS.md)、[AGENTS_Android.md](assets/项目模板/AGENTS_Android.md) | 在双端根目录维护各端补充说明与读取方式，由根入口明确引用，不写入源码仓库 |
| 各端既有规则与技能 | 只读核对已有内容和路径；不要求添加索引，不替换、复制或改写配置 |

从 `assets/项目模板/` 取用资源时包含隐藏目录 `.agents/`。本地任务记录模板与技能中的 [模板原稿](assets/双端任务记录模板.md) 保持一致，日常创建记录只引用项目本地副本。项目已有同职责协调技能时，合并到原位置并同步入口链接，而非强制采用模板目录名。

双端协作目录已有 `AGENTS.override.md` 时，将根入口的读取指引合并到其实际生效的文件。源码端的 override 仅决定读取顺序：不得因此改写源码端规则。初始化和更新默认只读源码仓库的 Agent 配置，不新增、修改、删除、搬动其 `AGENTS.md`、`AGENTS.override.md`、`.agents/`、技能或 Git 忽略配置；缺失项记录在双端目录。只有用户明确要求修改源码端配置时另行处理。各端补充只写在根 `AGENTS_iOS.md`、`AGENTS_Android.md`，两文件须按实际平台适配，不复制根 AGENTS.md 全文，也不复制源码规则或技能正文。

## 固化三个入口与单一维护位置

- 单端同事从源码仓库启动，使用本仓库规则和平台技能；双端开发者从协作目录启动，使用协调规则，再按已登记路径读取各端规则和技能。不要搬动源码仓库来适配模板。
- 根 `.agents/skills/` 只保存双端协调能力。不复制、镜像或自动建立平台技能软链接，不因技能同名就覆盖或合并正文；遇到重复来源先核对用途和维护位置，不擅自删除现有技能。
- 在协作入口写明：平台工作开始前，按真实路径读取该端既有规则、双端根目录的平台补充文件及按需选中的技能；已有技能索引可利用，没有索引时检查技能元数据，不要求修改源码端规则。加载对应 `SKILL.md` 和必要资源，资源相对路径以所属技能目录为基准。目录中有技能不代表已注册到当前会话的技能列表；一次 shell `cd` 也不能证明规则或技能自动重载。
- 自动发现主要沿启动目录向上扫描，不能假设从双端入口自动向下发现平台技能，也不能假设跨独立 Git 仓库自动继承父目录规则。按路径读取是本项目约定，不是自动注册机制。
- 双端协调技能要明确工程师 Agent 的输入：实际工程与仓库路径、适用源码规则、根平台补充文件和技能位置、共同契约、允许修改范围、验收项、验证入口及产物约束。初始化本身不派生 Agent。
- 技能或路径不存在时记录“缺失／待核对”，说明实际可继续的配置范围；不写假链接或声称能力已就绪。只有用户另行要求补齐时才处理技能安装或编写。

## 更新与收尾

- 更新前对照已有内容与本次需求，按语义合并。维护已有同职责段落和技能，不重复追加规则或生成带序号的副本；无差异则不重写。保留项目定制、历史任务记录、工具核对历史和并行改动。
- 项目路径优先采用可共享的相对路径，以项目说明所在目录为基准；外部绝对路径仅留本地实例，不带回通用模板。技能索引说明各路径的解析基准。凭证和带访问密钥的链接不得入文档。
- 用户仅维护通用模板时保持未绑定，只更新模板和已授权的当前协作资料，不在空 `iOS/`、`Android/` 中创建假工程或伪造已接入记录。
- 核对显式调用配置、Markdown 引用及已登记路径，检查双端入口和各端独立入口是否使用同一份平台技能；核对 override、生效规则和缺失状态。重复更新不应产生副本。静态核对不等于已执行模型行为测试或 App 验收。
- 交付说明已更新内容、实际维护位置、缺失项和验证边界。初始化完成不代表 App 构建或业务验收通过；不自动提交、推送或回写外部系统。
