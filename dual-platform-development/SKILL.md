# 双端项目初始化与更新

只负责建立或更新项目的协作配置。完成后停止，不自动进入功能开发、执行构建、派生工程师 Agent、克隆仓库、创建索引、安装工具或批量安装平台技能。日常开发使用项目自身的 `AGENTS.md` 和 `.agents/skills/`，不反向依赖本技能。

单端独立开发由对应源码仓库自身的 Agent 配置决定；本技能只维护双端协作配置，不替各端定义独立开发流程。双端协作配置须保留各端适用规则与匹配技能的按路径读取入口，使其正文和必要资源按需纳入双端任务上下文。

## 明确目标与核实工程

1. 用户主动调用后，区分初始化、更新已有配置或维护未绑定模板。先读取用户指定的资料、当前目录入口及项目说明；能从上下文和可见工程确定的信息直接核实，只询问阻塞当前配置的必要信息。不全盘搜索，不猜选历史 App。
2. 确定协作目录和各端实际工程、源码仓库根目录、Git 根目录及工程入口。工程可以位于外部路径，也可以同仓库；空目录、`未绑定` 和 `待核对` 不是工程接入证据。只核对现有文件和必要只读命令，不执行会解析依赖或生成工程文件的构建分析。
3. 对每个读取或修改目标，逐级检查实际 Git 根目录到目标目录的规则，每级优先 `AGENTS.override.md`，不存在时读 `AGENTS.md`；非 Git 目录从约定工程根目录开始。需要定位代码且存在 `.codegraph/` 时先用 CodeGraph，否则不创建索引。
4. 核实各端现有规则和技能入口，按实际需要读取技能元数据和引用。源码仓库既有平台技能保持在各自源码仓库的 `.agents/skills/`；已有用户级或插件能力可登记来源和依赖，不把本机可用误报成团队已安装。

## 生成或合并项目配置

按 [项目入口模板](assets/项目模板/AGENTS.md) 合并以下内容，已有文件先完整阅读，不用整目录复制覆盖项目：

| 内容 | 初始化或更新方式 |
| --- | --- |
| 协作目录 `AGENTS.md` | 合并项目入口及各端读取约定，移除要求日常开发加载本初始化技能的旧约定 |
| [双端项目说明.md](assets/项目模板/双端项目说明.md) | 登记已核实的工程、规则入口、技能目录及能力索引，不复制平台技能正文 |
| [使用说明.md](assets/项目模板/使用说明.md) | 说明用户主动初始化／更新与日常直接描述需求的区别 |
| [项目双端协作技能](assets/项目模板/.agents/skills/dual-platform-workflow/SKILL.md) | 合并双端协调技能及其本地任务记录模板；若已有同职责入口，优先整合，不再建立平行流程 |
| [独立任务协作技能](assets/项目模板/.agents/skills/codex-task-coordination/SKILL.md) | 将完整技能包部署到协作目录 `.agents/skills/codex-task-coordination/`；保留 `agents/openai.yaml` 的显式调用策略，安装不等于启用或创建聊天 |
| [任务协作配置.md](assets/项目模板/任务协作配置.md) | 合并调用项目自己的规则、路径、授权及验收入口；工程未绑定时保留待核对，不复制其他项目的聊天、运行记录或授权 |
| [AGENTS_iOS.md](assets/项目模板/AGENTS_iOS.md)、[AGENTS_Android.md](assets/项目模板/AGENTS_Android.md) | 在双端根目录维护各端补充说明与读取方式，由根入口明确引用，不写入源码仓库 |
| 各端既有规则与技能 | 只读核对已有内容和路径；不要求添加索引，不替换、复制或改写配置 |

从 `assets/项目模板/` 取用资源时包含隐藏目录 `.agents/`。本地任务记录模板与技能中的 [模板原稿](assets/双端任务记录模板.md) 保持一致，日常创建记录只引用项目本地副本。项目已有同职责协调技能时，合并到原位置并同步入口链接，而非强制采用模板目录名。

`codex-task-coordination` 的通用分发原稿维护在本技能的 `assets/项目模板/.agents/skills/codex-task-coordination/`。部署时包含 `SKILL.md`、`agents/`、`references/`、`assets/` 和 `scripts/`，排除缓存及验证产物；项目运行不反向依赖本机初始化技能或原项目。已有同名技能先核对来源并按语义合并，保留项目定制和运行记录，不整目录覆盖。根入口和日常协作技能只提供显式调用路由，不将它改为开发默认流程。项目配置文件名已有定制时保留原位置，同步两处入口链接；不另建一份同职责配置。

合并时区分跨聊天推进与聊天内执行：`codex-task-coordination` 管理较大需求的长期独立聊天、通信、交付和恢复，`dual-platform-workflow` 提供平台规则、共同契约、任务内 Agent 分工与验收依据。两层可同时使用，启用独立聊天协作不禁止聊天内部派生多个子 Agent；内部委派仍受所属聊天的职责、文件范围及授权约束。任务记录区分真实聊天身份与子 Agent 标识，不把两层改成互斥模式。

同步时保留 [启用价值评估](assets/项目模板/.agents/skills/codex-task-coordination/SKILL.md#启用价值评估)：实际启动前按独立交付单元、长期接续需要、依赖及资源比较直接执行、聊天内子 Agent 和独立聊天，记录任务数量依据；调用技能不强制建批次或聊天。初始化仅部署规则，不执行开发任务的组织评估或创建运行实例。

同步 [任务责任链](assets/项目模板/.agents/skills/codex-task-coordination/references/task-traceability.md) 的目标/父分派引用、接单理解确认和验收覆盖，保留原始需求与各层交付的关联；元数据由 Agent 维护，不把模板更新描述为工具已能自动理解需求或验收。

多级独立聊天按[多级协调协议](assets/项目模板/.agents/skills/codex-task-coordination/references/hierarchical-coordination.md)合并：层级按工作量启用，每组独立长期目录和批次，上下层关联消息与修订，每个仓库目标交付线指定唯一集成负责人。上层核对子组冻结交付，接续分别对账，不强制初始化完整层级，不改写既有聊天身份或运行记录；项目统一验收台账和平台限制继续保留。

共享任务按[通用技能中的两类触发条件](assets/项目模板/.agents/skills/codex-task-coordination/SKILL.md#共享任务的职责与触发条件)合并：仓库内多个并行模块确需修改同一公共实现，或多个仓库确需统一维护真实公共依赖时才考虑独立共享任务；只需跨端契约对齐时由协调者处理。保留公共来源、消费者、接入方式及既有维护归属，不默认生成“iOS＋Android＋共享任务”，也不按每个仓库固定增加共享角色。

同步 [分支基线与最终集成](assets/项目模板/.agents/skills/codex-task-coordination/references/code-delivery.md)：实际协作启动时，各源码仓库以当时当前分支为最终目标、当时 HEAD 为 worktree 创建起点；目标分支可正常持续推进。模块只按清单 cherry-pick 共享代码，终版共享及模块交付集中 rebase 到该目标最新状态，去重、复验后快进回写。集成优先安全复用原目标工作区，候选 worktree 按需隔离；按原稿的工作区选择与回写条件合并，不重新引入“必须独立候选 worktree”的默认限制。初始化只部署规则，不采样或固定活动分支、不创建 worktree 或执行 Git 集成；同步时保留项目定制并明确处理与旧最终 cherry-pick 策略的冲突。

同步[工作区目录与聊天、分支对应](assets/项目模板/.agents/skills/codex-task-coordination/references/worktree-layout.md)：新任务按真实源码位置，在原源码仓库所在父目录下建立与仓库并列的 `worktree/需求简称/平台/任务目录`；同父目录可共用根，不同父目录按仓库分别登记，不固定跟随 test 或协作配置目录。保留真实源码路径及既有目录定制，区分资料入口、Git worktree 与聊天执行环境，沿用长期目录的工作区映射。共享任务和目录按需建立，协调工作区优先安全复用；初始化只部署规则，不创建这些运行目录、不绑定真实聊天或搬移旧工作区，构建及证据产物仍遵守原约束。

通用职责按实际角色和已分配源码界定：单 Agent、模块或共享任务内部主 Agent 可在自身授权范围直接编码、修复和验证，也可派生子 Agent；多 Agent／多独立任务中的协调者不接管已分配给其他执行者的源码，明确留给自己的工作仍可执行。调整已分配范围前先核对在途动作和工作区，确认原执行者停止相关写入并记录职责交接。不要将协调角色的范围限制推广成“主 Agent 一律不编码”。若目标项目另有明确且更严格的定制，按下文冲突流程列出具体条款和影响；本次用户未授权改变时不静默覆盖，也不把它带回通用原稿。

双端协作目录已有 `AGENTS.override.md` 时，将根入口的读取指引合并到其实际生效的文件。源码端的 override 仅决定读取顺序：不得因此改写源码端规则。初始化和更新默认只读源码仓库的 Agent 配置，不新增、修改、删除、搬动其 `AGENTS.md`、`AGENTS.override.md`、`.agents/`、技能或 Git 忽略配置；缺失项记录在双端目录。只有用户明确要求修改源码端配置时另行处理。各端协作规则补充维护在根 `AGENTS_iOS.md`、`AGENTS_Android.md`，需要按任务加载的个人补充能力可放在根 `.agents/skills/`。两份规则文件须按实际平台适配，不复制根 AGENTS.md 全文，也不复制源码规则或技能正文。

## 固化三个入口与单一维护位置

- 单端同事从源码仓库启动，使用本仓库规则和平台技能；双端开发者从协作目录启动，使用协调规则，再按已登记路径读取各端规则和技能。不要搬动源码仓库来适配模板。
- 根 `.agents/skills/` 允许保存双端协调能力及本协作入口使用的个人补充技能，包括 iOS、Android 专项能力。源码仓库既有平台技能保持原位，按路径复用，不复制、镜像或自动建立软链接；不因同名就覆盖或合并正文，遇到重复来源先核对用途和维护位置，不擅自删除现有技能。
- 在协作入口写明：平台工作开始前，按真实路径读取该端既有规则、双端根目录的平台补充文件及按需选中的技能；已有技能索引可利用，没有索引时检查技能元数据，不要求修改源码端规则。加载对应 `SKILL.md` 和必要资源，资源相对路径以所属技能目录为基准。目录中有技能不代表已注册到当前会话的技能列表；一次 shell `cd` 也不能证明规则或技能自动重载。
- 已被当前会话发现的根补充技能，按名称、描述与任务选择，不要求在 `AGENTS_iOS.md` 或 `AGENTS_Android.md` 重复登记索引；需要固定使用、消除歧义或补足发现范围时，再提供必要指引。发现元数据不等于已加载正文，选中后仍读取 `SKILL.md` 和必要资源。
- 自动发现主要沿启动目录向上扫描，不能假设从双端入口自动向下发现源码仓库技能，也不能假设跨独立 Git 仓库自动继承父目录规则。按路径读取是本项目约定，不是自动注册机制。
- 双端协调技能要明确工程师 Agent 的输入：实际工程与仓库路径、适用源码规则、根平台补充文件和技能位置、共同契约、允许修改范围、验收项、验证入口及产物约束。初始化本身不派生 Agent。
- 技能或路径不存在时记录“缺失／待核对”，说明实际可继续的配置范围；不写假链接或声称能力已就绪。模板随附的协调技能按本次初始化部署；其他缺失能力只有用户另行要求补齐时才处理安装或编写。

## 已有项目的安全更新与冲突处理

1. **限定本次增量。** 先明确目标项目、更新主题和原稿来源。用户只要求同步某项修正时，只合并相关技能、入口及模板的必要条款，不顺带刷新其他章节、工具实现、平台配置或运行资料。调用本技能是按下述流程执行更新，不是整目录覆盖命令。
2. **保存现状并核实基线。** 完整读取目标内容及适用规则，记录已有工作区和暂存区状态，为本次目标保存文件快照及指纹。存在可核实的上次原稿或版本时，以“旧原稿／新版原稿／项目现状”对照；没有旧基线时明确说明，仅作现状与新版的语义比较，不能把所有差异都视作项目落后或声称已完成三方合并。
3. **分类差异并暴露冲突。** 区分本次可合并增量、应保留的项目定制、与本次无关的差异，以及待决冲突。项目定制包括工程路径、职责、授权、验收矩阵、工具与运行资料位置；同名技能不代表可覆盖。新版通用默认与项目明确限制不同时，保留并明确报告该限制，不自动放宽。若同一条款无法兼容、来源不明或合并将改变业务/权限边界，列出文件与章节、现有规则、新版规则、影响及待决定项，保留原文并暂停依赖它的更新，其他独立且确定的部分可继续。用户已明确授权替换的旧行为按该授权处理，不重复索要确认。
4. **定点合并并复核。** 写入前复核目标指纹；发现其他任务或用户已修改时重新读取和比较，不按旧快照落盘。只修改已核实的条款，不通过模板覆盖、选择一边全文或重复追加来消除冲突。保留原有暂存内容、历史记录和无关修改，不自动暂存、提交或推送。复核实际 diff、入口及资源引用、技能配置和项目定制；有待决冲突时不得报告完整同步成功。
5. **交付更新清单。** 说明已更新、保留及未合并的内容和理由，列出待决冲突与验证边界。记录本次实际使用的原稿来源及比较基线；缺少基线仍如实说明，不伪造版本关系，也不承诺无需审查的自动同步。

## 更新与收尾

- 更新前对照已有内容与本次需求，按语义合并。维护已有同职责段落和技能，不重复追加规则或生成带序号的副本；无差异则不重写。保留项目定制、根个人补充技能、历史任务记录、工具核对历史和并行改动，不按模板文件清单清理已有补充技能。
- 项目路径优先采用可共享的相对路径，以项目说明所在目录为基准；外部绝对路径仅留本地实例，不带回通用模板。技能索引说明各路径的解析基准。凭证和带访问密钥的链接不得入文档。
- 用户仅维护通用模板时保持未绑定，只更新模板和已授权的当前协作资料，不在空 `iOS/`、`Android/` 中创建假工程或伪造已接入记录。
- 核对显式调用配置、Markdown 引用及已登记路径，检查双端入口和各端独立入口是否使用同一份平台技能；核对 override、生效规则和缺失状态。重复更新不应产生副本。静态核对不等于已执行模型行为测试或 App 验收。
- 检查独立任务技能完整性与 `allow_implicit_invocation: false`，确认未携带任何来源项目的运行目录、真实聊天 ID、源码路径或授权。项目配置中的未绑定项不能被写为已就绪；初始化不创建长期任务目录或批次实例。更新消息工具或协议时，在外部验证目录运行包内回归测试，不向项目写入模拟消息、Git 夹具或测试缓存。
- 核对共享任务的选择条件和模板角色：两类共享职责、来源仓库与消费者、同仓库提交接入和跨仓库依赖交付应一致；无共享任务时不等待空交付。已有项目的角色／平台参考限制按语义合并，不能因模板更新覆盖定制或转移已有职责。
- 核对入口、两份协作技能、参考资料、项目配置及任务/批次模板中的职责措辞：单 Agent 和模块内部主 Agent 的实现能力、协调者不接管已分配源码及职责交接条件须一致，避免旧模板或角色描述重新引入全面禁编码的默认值。初始化技能本身只做配置、不开发 App 的职责保持，不与日常执行者的编码权限混淆。
- 按单 Agent、多 Agent、独立聊天内部派生及中断接续检查规则适用范围：接续重新派生前核对旧执行者、在途写入及职责交接，不能把聊天中断或无汇报当作旧执行者已停止。仅维护配置不创建运行批次的边界，不限制之后已获授权的实际执行。
- 交付说明已更新内容、实际维护位置、缺失项和验证边界。初始化完成不代表 App 构建或业务验收通过；不自动提交、推送或回写外部系统。
