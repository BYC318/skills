# 输入证据与工作区清理

## 附件核对

逐件记录附件类型、打开结果、可观察事实以及对应复现步骤。图片查看原图；视频至少完整播放一次，摘要包含操作顺序、关键时间、页面进退、等待和最终结果。文件名、缩略图、时长、首帧和旧评论均不能代替查看。

将附件与环境、文字步骤、实际/预期和最新评论逐项比对。关键附件无法下载、播放或解码时，记录尝试与具体阻塞，只阻塞该 Bug 并继续其他独立 Bug。可以证明与判断无关的附件才可排除，必须记录依据。自动测试、用户验收和修复后截图均不能补足未查看的输入附件。

## UI 修复截图

候选范围确认后逐 Bug 明确记录 `ui_bug`。预期结果包含用户可见的布局、文字、图片、图标、颜色、层级、方向、状态或交互反馈变化时记为 `true`；纯数据、网络、崩溃或后台逻辑且预期不包含可见 UI 结果时记为 `false`。不能因为截图难获取而把 UI Bug 标成非 UI。

UI Bug 必须满足以下输出证据门禁：

- 使用修复后的最终实现，在 Simulator、真机或可审计 UI 测试运行时截图；设计稿、TAPD 原始附件、修复前截图和源码截图不能充当修复结果。
- 至少一张截图同时看得出所在页面和本 Bug 的修正区域。多个 Bug 可以共用一张截图，但每个 Bug 都必须能从该图直接识别自己的修正结果，并分别上传到对应 TAPD Bug。
- 截图保存在仓库外的项目规定证据目录，记录绝对路径和文件 SHA-256；上传前检查图片可打开且不包含账号、Token、真实用户隐私或其他不应进入 TAPD 的内容。
- rebase、冲突解决或最终验证改变了相关 UI 实现时，旧截图失效，必须针对最终源码重新运行并截图。
- 动画、加载、刷新、手势、跳转和其他时序问题仍需视频或自动化流程证据说明过程；单帧不能证明过程正确，但仍须留下最终可见状态截图。

无法进入目标页面、无法生成合格截图或截图与最终源码不一致时，该 UI Bug 不能进入 `VALIDATED`。截图已经生成但上传或回读失败时，保留 Git 结果并将 TAPD 交付记为 `PARTIAL`，不得流转“已解决”。

重开 Bug 必须重读最新内容和原始/新增/替换附件。旧附件只有存在逐件已查看记录且确认内容未变时才能复用。区分原修复遗漏、回归和新增需求；不得仅凭旧修复结论给出根因。

## 修复边界

明确引用的 iOS 参考端提供业务与 API 行为，设计稿提供视觉依据；遵循项目对应规则。低风险、可逆且不扩大范围的细节可以按项目惯例实施并记假设；实质改变功能、数据兼容、接口或安全的歧义阻塞对应 Bug。

判断不成立、重复或不属于项目时仅记录证据，不自动拒绝、关闭或修改责任人。TAPD 写入授权仅覆盖本批修复后的评论、可靠截图与开发状态“已解决”；Git 同步和蒲公英交付按主流程执行。拒绝仍需用户明确指定。

## 隔离与清理

默认当前目录。指定隔离时使用当前 HEAD 为默认基线（用户指定优先），新建 `codex/tapd-<batch-id>`，一批最多一个新 worktree。使用技能绝对路径定位 `scripts/worktree.sh --repo=<root> create <branch> --base=<resolved-base>`。多个 Podfile 时根据当前 App workspace 选择；仍有歧义才询问。Pods/索引初始化失败保留目录并报告。

没有隔离指令不得因为 linked worktree 或脏状态擅自新建；只提交本轮可独立暂存的增量。被阻塞 Bug 的未完成改动须在同步前完成或安全撤回；用户原有未提交改动保持原样。工作树不干净时暂停 rebase、推送和打包，不能把失败修复当成用户原有改动或混入 IPA。

仅在用户明确表示已 rebase 合并并请求/确认清理时删除。先读取本批记录的实际目录、分支和基线，更新对应远端引用；要求目标 worktree 完全干净。验证 `git merge-base --is-ancestor <branch> <base-ref>`，失败时检查 `git cherry <base-ref> <branch>`：只有相关提交全部为 `-`、没有 `+` 且映射明确时认定补丁等价。用原脚本 `remove <branch>`；不传 force，不运行 branch -D。删除 worktree 成功但分支删除失败时保留分支并报告。
