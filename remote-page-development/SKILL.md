# 远程数据页面开发

开发页面前先冻结请求状态流转，再写网络调用和 UI。列表与非列表遵循相同的结果语义；Loading 载体由页面是否具有下拉刷新控件决定。

## 适用性门禁

任何 Swift UIKit 页面开发、修改、重构或审查任务都先执行本门禁：

1. 判断页面是否读取远程数据，包括首次接口请求、详情或余额加载、表单初始值、卡片数据、刷新或分页。
2. 页面读取远程数据时，完整执行本技能的请求状态流转，不得只实现成功态。
3. 页面是纯静态页面时，记录“远程数据状态流转不适用”及依据，不添加状态机、HUD、空态或错误视图，然后退出本技能。
4. SwiftUI 页面不适用本技能。

## 开发前检查

先检查目标项目和相邻页面已有的：

- 下拉刷新头、加载更多 Footer 及其程序化开始/结束方式；
- 页面级活动 HUD、短提示、空态、错误视图和 Retry 组件；
- 网络错误分类、服务端业务错误、账号失效和取消语义；
- 页面退出、请求替换和迟到响应隔离；
- 已有内容刷新时的候选数据提交方式。

复用目标项目已有能力，不复制第二套刷新控件、HUD、错误视图或请求状态模型。先明确什么是该页面的“成功有数据”和“成功无数据”；只有成功响应得到的业务空结果才能进入空态。

## Loading 载体

同一次请求只能有一种 Loading 载体：

1. 页面具有下拉刷新控件时，首次请求、用户下拉刷新和网络错误 Retry 都使用该刷新控件。首次进入和 Retry 必须程序化进入用户可见的刷新状态，不再叠加页面级活动 HUD。
2. 页面没有下拉刷新控件时，首次请求和网络错误 Retry 使用目标项目已有的页面级活动 HUD。目标项目指定 GPProgressHUD 时，必须复用现有展示入口，不能在页面扫描 Window 或另造 Spinner。
3. 分页加载使用目标项目已有的加载更多 Footer，不与刷新头或页面级 HUD 同时表示同一次分页请求。
4. 成功、失败、业务拒绝、登录失效、取消和页面失效都必须结束对应 Loading。迟到响应不能重新改变已离开或已切换参数的页面。

## 状态流转

“已有数据”包括列表记录，也包括详情、余额、表单初始值、卡片或其他已经成功展示的远程内容。

| 请求与结果 | 无旧数据 | 已有数据 |
| --- | --- | --- |
| 请求开始 | 隐藏空态和错误视图；显示刷新控件或页面级 HUD | 保留当前内容；显示对应刷新控件、HUD 或分页 Footer |
| 成功且有数据 | 结束 Loading，展示内容 | 成功提交本次内容后结束 Loading |
| 成功但业务数据为空 | 结束 Loading，展示空态，不显示 Retry | 按页面业务语义提交空结果并展示空态 |
| 明确的网络错误 | 结束 Loading，展示完整网络错误视图和 Retry | 保留内容与交互位置，结束 Loading，通过项目短提示展示网络错误 |
| 服务端业务拒绝 | 结束 Loading，展示完整错误视图和服务端可见文案，不显示 Retry | 保留内容，结束 Loading，通过项目短提示展示服务端文案 |
| 解码或响应格式错误 | 结束 Loading，展示通用错误视图，不显示 Retry | 保留内容，结束 Loading，通过项目短提示展示通用错误，并记录脱敏诊断 |
| 登录失效 | 结束 Loading，进入项目账号失效流程 | 结束 Loading，进入项目账号失效流程 |
| 请求取消 | 静默恢复请求前状态 | 静默保留请求前内容、游标和交互位置 |

网络错误只能来自目标网络层的明确分类，例如离线、连接失败、连接中断或超时；不得通过错误文案字符串猜测。只有明确网络错误显示 Retry。服务端业务拒绝、解码错误、登录失效和取消均不显示普通 Retry。

## Retry

网络错误视图的 Retry 必须遵循：

1. 保留导致当前错误的请求参数、筛选、路由上下文和请求语义；
2. 点击后立即隐藏错误视图；
3. 页面有下拉刷新控件时程序化显示刷新 Loading，否则显示页面级活动 HUD；
4. 只重试原页面数据查询，不预先制造空态；
5. 成功有数据进入内容态，成功空结果进入空态，网络仍失败才重新显示带 Retry 的网络错误视图；
6. 如果本次返回服务端业务拒绝或解码错误，改为对应的不带 Retry 错误视图。

本规则的 Retry 只适用于页面数据查询。购买、提交、兑换、删除、发送等写操作必须依据接口幂等契约、服务端规则或已确认的产品行为单独设计，不能因本技能自动重试。

## 旧数据与提交不变量

- 刷新已有内容时不得在请求开始清空当前数据。
- 刷新使用候选结果；只有请求成功并完成必要归一化后才原子替换可见内容，失败或取消继续展示请求前内容。
- 分页成功后追加、去重并采用服务端后续游标；分页失败保留内容与失败页游标。
- 空态不能由网络错误、业务拒绝、解码失败、取消或加载过程中的临时空值触发。
- 全页错误视图只用于没有可保留内容的失败；已有内容后的失败不得用错误视图遮挡内容。
- 服务端文案只有在确认可面向用户展示时才直接使用；空文案或内部诊断文案回退到项目本地通用错误文案。

## 状态建模

页面状态至少能够互斥表达：尚未请求、首次加载、内容、成功空态、无旧数据的网络错误、无旧数据的业务错误、无旧数据的响应错误、已有内容刷新中和已有内容分页中。

持续页面状态与一次性短提示、账号动作和导航动作分开表达。不要只用互相独立的 `isLoading`、`isEmpty` 和 `hasError` 拼装界面，否则容易同时出现 Loading、空态和错误视图。

## 验证门禁

实现完成前至少验证：

- 有下拉刷新控件的页面在首次进入与网络 Retry 时展示刷新动画，且不同时显示页面级 HUD；
- 无下拉刷新控件的页面在首次进入与网络 Retry 时展示并正确结束页面级 HUD；
- Retry 点击后立即隐藏错误视图，并保持 Loading 直到请求结束；
- 成功有数据、成功空结果、网络错误、业务拒绝和响应错误互斥；
- 只有网络错误视图包含 Retry；业务拒绝展示服务端文案但没有 Retry；
- 已有数据后的刷新或分页失败保留内容，分页失败还保留失败页游标；
- 登录失效走账号流程，请求取消静默恢复；
- 刷新候选结果只在成功后替换旧内容；
- 页面退出、参数切换或新请求开始后，迟到响应不会覆盖当前页面。

状态测试验证数据保留、Retry、游标、取消与迟到响应；UI 测试或目标运行证据验证 Loading、内容、空态、错误视图、按钮和层级。构建通过或直接构造展示模型不能替代状态流转验证。
